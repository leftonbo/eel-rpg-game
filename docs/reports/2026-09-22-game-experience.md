# 戦闘で得た成長を、そのまま次の挑戦に使えるようにする

2026-09-22 / T048 / ブランチ: `codex/T048-game-experience`

## 実プレイで見つけた課題

新規データから闇のおばけに挑み、攻撃、回復薬、もがく、なすがまま、敗北後の演出、結果確認、装備画面まで操作した。機械のクモでも攻撃と中断を確認した。前半はChromeのブラウザ連携、後半はWSLの独立したPlaywright Chromiumを使用した。本人のセーブデータには触れていない。

敵の台詞や、拘束・敗北後にも続く固有の演出はこのゲームの良さだと判断した。今回の変更では、この流れと戦闘バランスを保ちながら、結果を受け取って次へ進む操作を改善した。

| 優先度 | 再現条件と観測 | 体験への影響 |
| --- | --- | --- |
| 高 | 闇のおばけに敗北しても、行動欄には「なすがまま」しか残らない。画面左下の「ボス選択に戻る」で初めて結果へ進めた | 演出を終えるタイミングと、経験値を受け取れることが分かりにくい |
| 高 | 結果で新装備を解禁しても、戻った選択画面はHP100・攻撃力10・無装備のまま | 成長を実感する前に、同じ条件で再挑戦しやすい |
| 中 | タフネスLv.0→2の結果に「旅装」は出るが、途中の「Tシャツ」「防御」が出ない | 新しく選べる装備・行動を見落とす |
| 中 | 攻撃後の1秒間、見た目の無効化はあるが、待機理由の表示とネイティブのdisabled属性がない | 入力が受け付けられない理由が分かりにくく、キーボード操作にも不整合がある |
| 高 | 機械のクモに攻撃直後、結果へ移動しても、古い戦闘ログに敵の拘束とラウンド2が追加された | 結果確認や再挑戦に、前の戦闘の予約処理が混ざる |

## 3案を比較し、任意の装備更新と再挑戦を採用

| 案 | 効果 | 実装費用 | 欠点・判断 |
| --- | --- | --- | --- |
| 初回の強制チュートリアル | 成長と装備の仕組みを順に説明できる | 中。説明画面と初回管理が必要 | 再プレイ時の操作は減らない。今回は見送った |
| 戦闘後に最強装備へ自動変更 | 必ず強くなった状態で次へ進める | 小。既存の装備処理を再利用できる | 意図して選んだ装備も変わる。今回は見送った |
| 結果画面で任意に最強装備へ変更し、同じボスへ再挑戦 | 報酬を確認した場で次の準備を済ませられる | 小。既存の装備・ボス選択処理を再利用できる | 自動ではないので説明が必要。採用し、短い説明を併記した |

装備更新を強制しないため、演出鑑賞や任意の装備で遊ぶ自由も残る。ボスの強さ、経験値量、解禁条件、敗北後の演出は変更していない。

## 実装した内容

- 敗北後の行動欄に結果へ進むボタンと説明を表示。「なすがまま」で演出を続ける操作も残した。
- 結果の見出しに勝利・敗北・中断を表示。任意の「最強装備に変更」「同じボスに再挑戦」を追加した。
- 結果画面の操作をスクロール領域の外へ移し、長い報酬一覧でも操作できるようにした。
- 複数レベル上昇時は、通過した全レベルの装備・アイテム・スキルを通知する。
- 自分のターン／相手の行動待ちを表示し、基本・特殊行動のボタンをネイティブでも無効化する。
- 戦闘シーンから離れたときに、予約された敵ターンを取り消す。

表示には既存のReact、Bootstrap、日英の翻訳リソースを使用した。依存パッケージとセーブ形式の変更はなく、マイグレーションは不要。装備は本人が結果画面のボタンを押した場合にだけ変更する。

## 再プレイで改善を確認

新規データの闇のおばけ戦では、17回の行動後に敗北し、行動欄から結果へ進めた。そこで装備を更新して再挑戦すると、HPは100→120になり、攻撃で13ダメージを与えた。敵のHPと戦闘中の状態異常も新しい戦闘用に戻った。ダメージには乱数があるため、13という値そのものを成功条件にはしていない。

| 確認 | 結果 |
| --- | --- |
| 敗北後の結果確認と演出の継続 | 両方の操作が可能 |
| 装備変更と再挑戦 | 新しい防具が次の戦闘に反映された |
| 攻撃直後の中断→即再挑戦 | 旧タイマーの期限を過ぎてもラウンド1のまま。古い敵ターンは実行されない |
| 報酬の重複、セーブ維持 | 再挑戦で報酬を二重付与せず、再読み込み後も装備を維持 |
| 1280×900、390×844、320×568 | 結果画面の3操作が画面内に収まる。390px幅は画像でも確認 |
| 英語表示 | ターン表示、結果見出し、装備更新・再挑戦・戻るの文言を確認 |
| 勝利から再挑戦 | デバッグ画面で敵HPを1にした検証用状態から攻撃して確認。通常プレイでの勝利・難易度評価とは分けて扱う |
